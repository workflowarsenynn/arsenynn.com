# arsenynn.com — полное описание проекта для deep research
LastUpdated: 2026-11-01 13:40 MSK

Документ описывает проект целиком: кто автор, какие у него проекты, что уже сделано на сайте, как он выглядит и почему, на чём работает, какие есть ограничения и куда сайт должен вырасти. Он написан как вход для глубокого исследования: исследователь должен понять каждый нюанс и предложить самые современные и при этом проверенные решения. В конце есть готовый промт.

Живой сайт: https://arsenynn.com
Код: https://github.com/workflowarsenynn/arsenynn.com (публичный)
Исходное ТЗ владельца: `docs/brief.md` в репозитории, 54 раздела.

---

## 1. Кто такой @arsenynn

@arsenynn — это не человек-бренд и не один Telegram-канал, а **зонтичная авторская идентичность**: один автор, несколько очень разных параллельных проектов. Среди них художественные, философские, музыкальные, инженерные, коммерческие и настоящие продукты с инфраструктурой.

Главная мысль сайта, которую нужно передать структурой, а не текстом:

> Здесь не список моих соцсетей. Здесь индекс разных вещей, которые я делаю.

Формула проекта от владельца: **film / magazine / index, not portfolio template**. Сайт должен ощущаться как нечто между независимым журналом, титрами фильма, авторским индексом и минималистичным цифровым каталогом. При этом по удобству он должен работать как хороший современный мобильный интерфейс.

Чем сайт быть **не должен**: Linktree, Taplink, Bento, корпоративным портфолио, CV со списком профессий («filmmaker / developer / producer…»), агентским шаблоном, дизайнерским мокапом.

## 2. Семь проектов

Сейчас у автора семь направлений. Почти весь их контент живёт в Telegram: каналы — главный носитель. У части проектов есть свои сайты и боты.

### 01. @arsenynn — главная авторская линия
- **Суть:** художественные и философские видео. Материалы делятся на главы. Видео, места, люди, мысли и визуальные фрагменты постепенно складываются в более крупную структуру. Это не lifestyle-канал, не портфолио и не блог.
- **Теги:** concept / chapters / identity
- **Контент:** видео (кино), главы, наблюдения, фото, тексты.
- **Ссылка:** Telegram https://t.me/arsenynn
- **Будущее:** отдельный большой мир внутри сайта: главы, фильмы, тексты, изображения, архив, связи между материалами.

### 02. workflow@arsenynn — коммерческое видео
- **Суть:** профессиональная сторона видеопроизводства: ролики для брендов, промо, event-видео, съёмка, монтаж, режиссура, продюсирование. Это точка входа для заказчиков.
- **Теги:** production / promo / events / commercial video
- **Ссылки:** Portfolio https://portfolio.arsenynn.com/video-production/ (главное действие), Telegram https://t.me/ww_arsenynn
- **Особенность:** портфолио должно быть доступно сразу, без раскрытия описания. У портфолио есть разделы `/video-production/`, `/sales-events/`, `/it-ai/`, оно уже работает на GitHub Pages.
- **Будущее:** кейсы, шоурил, видео прямо на сайте, контакт для заказа.

### 03. «Бессмысленность и скоротечность» — пространство разговора
- **Суть:** не просто канал, а среда. Внутри работает бот **ann**: участвует в разговоре, хранит контекст, работает с памятью и возвращает старые материалы обратно в поток. Центральная идея: контент не обязан исчезать после публикации, некоторые вещи становятся понятны спустя месяцы или годы.
- **Теги:** philosophy / impermanence / dialogue / memory
- **Ссылка:** Telegram https://t.me/bessmislennost
- **Визуальный язык:** знак **NN** (красный, рукописный), персонаж ann: пожилой мужчина с седой бородой в тёмных очках и кепке с надписью «Бессмысленность и скоротечность» каллиграфическим шрифтом, красно-оранжевый свет, тёмный фон, звёздное небо на кепке.
- **Будущее:** страница о философии проекта, механике памяти и рециркуляции контента, о ann.

### 04. Without Streaming — личное интернет-радио
- **Суть:** выросло из канала с музыкой и визуальными материалами. Сейчас это настоящий radio runtime, постоянно идущий эфир, а не плейлист. Музыка, архив, визуальные фрагменты и личный вкус в одном потоке.
- **Теги:** radio / music / archives / fragments
- **Ссылки:** Listen https://radio.arsenynn.quest (главное действие, это не Telegram), Telegram https://t.me/without_streaming. Есть Mini App: https://t.me/without_streaming_bot/without_streaming
- **Знак:** монограмма **Ws** (белая кисть-каллиграфия).
- **Будущее:** плеер прямо на сайте, постоянное воспроизведение при переходах между страницами, архив эфиров.

### 05. annFlow — инженерная сторона
- **Суть:** AI, автоматизация, агенты, workflows, автоматизация macOS, инфраструктура, собственные сервисы, LLM. Не tech-блог, а «машинное отделение» всей системы @arsenynn: как всё это строится и работает.
- **Теги:** automation / AI / systems / agents / workflows
- **Ссылка:** Telegram https://t.me/annsflow
- **Логотип:** рукописный wordmark «aNNFlow»: буквы «NN» красные, остальное белое, резкая кисть. Есть иконка приложения со знаком `>_`. На фото видно, что логотип вырабатывался десятками рукописных эскизов.
- **Будущее:** вероятно, один из самых больших разделов: страницы проектов, технические заметки, архитектуры, кейсы, живые статусы, демо, GitHub, статьи.

### 06. Party Protocol — VPN-продукт
- **Суть:** независимый VPN-сервис со своей инфраструктурой и control plane, своим сайтом и Telegram-ботом (`@partyproto_bot`). На этом сайте он представлен просто как один из проектов автора, без технических деталей.
- **Теги:** VPN / privacy / secure access
- **Ссылки:** Website https://partyprotocol.arsenynn.quest (главное действие), Telegram https://t.me/partyprotocol
- **Визуальный язык:** чёрная маска-«очки» (силуэт карнавальной маски), афро-силуэт, гранжевая кистевая надпись PARTY и жирная курсивная PROTOCOL, фон горчично-жёлтый (#F0B030 примерно) с текстурой ткани.
- **Будущее:** страница продукта или ссылка на его собственный сайт.

### 07. Travel Log — формирующаяся линия
- **Суть:** не travel-блог. Путешествия соединяются с фотографией, видео, историей, литературой, памятью и географией. Пример: материал о Шри-Ланке соединяет современные фото и видео с литературными текстами о Цейлоне.
- **Теги:** places / stories / memory / literature
- **Статус:** публичного канала пока нет. Показывается «Coming soon», ссылки-заглушки запрещены.
- **Визуальное настроение:** фото крыла самолёта ночью в красном свете, звёзды.
- **Будущее:** карта или журнал мест, длинные материалы.

### Связи между проектами
- Буквы **NN** проходят через ann (бот), «Бессмысленность» и annFlow: это общая «ann»-линия.
- В паттерне workflow встречаются знаки **WW / NN**.
- Красный wordmark @arsenynn есть в фирменном написании workflow@arsenynn.
- Все проекты объединяет автор, тёмная гамма и красный цвет.

## 3. Аудитория и контекст

- **Главное устройство — телефон.** Люди открывают ссылку из Telegram, Instagram или переписки, чаще всего на iPhone.
- **Язык:** русский. Названия проектов и теги на английском. Двуязычность возможна в будущем.
- **География:** основная аудитория в России. Это жёсткое техническое ограничение (раздел 7).
- **Сценарий первого визита:** за несколько секунд понять, кто это и какие есть направления, найти интересный проект и одним нажатием перейти в Telegram, на радио, в портфолио или на сайт VPN.
- **Отдельный сценарий:** потенциальный заказчик видео должен сразу найти портфолио.
- **Превью в Telegram** при отправке ссылки особенно важно: многие впервые увидят сайт именно как карточку в чате.

## 4. Версии сайта

### v1 — индекс со ссылками (сделана, работает на arsenynn.com)
Одна страница. Каждый проект: номер, название (логотип или знак), теги, одна фраза, прямые ссылки. Подробности раскрываются внутри строки по кнопке About. Внизу блок Work / Collaboration. Цель v1 — идеальная минимальная точка входа.

### v2 — сайт с контентом (следующий шаг, ради него нужен research)
Контент, который сейчас живёт по ссылкам (в Telegram, на радио, в портфолио), начинает жить и на самом сайте:
- **видео:** фильмы и главы @arsenynn, коммерческие работы workflow, шоурил;
- **фото:** кадры, места, Travel Log;
- **тексты:** главы, заметки annFlow, философия «Бессмысленности», литература Travel Log;
- **радио:** плеер Without Streaming, возможно постоянный между страницами;
- **страницы проектов:** у каждого проекта уже зарезервирован маршрут: `/arsenynn`, `/workflow`, `/bessmyslennost`, `/without-streaming`, `/annflow`, `/party-protocol`, `/travel-log`. Включаются по одной, флагом `detailPageEnabled`.

### Дальше (идеи владельца из ТЗ, не план)
Архив, связи между материалами, система глав, карта Travel Log, живые статусы annFlow, возможная двуязычность RU/EN. Каждый раздел может получить свой, более сильный визуальный язык, но главная страница остаётся единой системой @arsenynn.

### Вопрос, который нужно решить в research
Как организовать v2, если основной источник контента это Telegram-каналы: вести контент вручную в репозитории, через headless CMS, через автоимпорт из Telegram или гибридно? Как не превратить сайт в зеркало Telegram и сохранить авторскую подачу?

## 5. Бренд и визуальная идентичность

### Ключевые слова владельца
**quiet, editorial, cinematic, minimal, precise.**
Минимализм здесь означает не «мало дизайна», а «каждый оставшийся элемент нужен».

### Порядок работы над дизайном (зафиксирован владельцем)
UX → иерархия → типографика → отступы → адаптив → контент → визуальная индивидуальность.
Причина: прошлые прототипы начали оформлять атмосферу раньше, чем решили интерфейс.

### Приоритеты при конфликте
- красивое vs читаемое → **читаемое**
- необычное взаимодействие vs очевидное → **очевидное**
- атмосфера vs скорость → **скорость**
- desktop-композиция vs удобство на телефоне → **телефон**
- много информации vs ясность → **ясность**
- визуальный эффект vs авторский характер → не путать эффект с характером

### Логотипы и знаки (оригиналы в `assets/logos/`)
| Проект | Логотип | Стиль |
|---|---|---|
| @arsenynn | wordmark `@arsenynn` | очень узкий высокий гротеск, красный `#CF0100`, своеобразные формы букв (y с длинным хвостом, @ прямоугольный) |
| workflow@arsenynn | `WORKFLOW` белым + `@arsenynn` красным | узкий гротеск; есть только версия с глитчем, чистого файла нет |
| Бессмысленность | знак NN | красная рукописная кисть, `#D02100`; персонаж ann |
| Without Streaming | монограмма Ws | белая каллиграфическая кисть; есть версия в чёрном круге |
| annFlow | wordmark aNNFlow | рваная кисть, белый + красные NN; иконка с `>_` |
| Party Protocol | маска + PARTY PROTOCOL | чёрный силуэт маски, гранжевая кисть, жёлтый фон |
| Travel Log | нет | — |

Важно: логотипы очень разные по стилю (узкий гротеск, каллиграфия, рваная кисть, силуэт). Задача дизайна — сохранить характер каждого и при этом удержать одну систему на главной.

### Что владелец отверг
**Прошлые концепты сайта:** перегружены графикой, слишком много фото, мелкий текст, неудобно на телефоне, слишком много информации сразу, проекты как декоративные карточки, гранж, шум, кинотекстуры, декоративная типографика, атмосфера выше удобства, вид дизайнерского мокапа.

**Макеты, нарисованные GPT** (в репозитории `docs/references/`): тёмный фон с шумом, портрет в красном свете в hero, «A simple index of parallel worlds» засечками, семь карточек со скруглённой рамкой, в каждой номер, логотип проекта, теги через красные точки и красная кнопка ⊕. При раскрытии фото «ON AIR» неоновое, красные glow-кнопки Listen / Telegram, кнопка Portfolio с красным свечением. Владелец: «мне не нравится как это выглядит, хочу стильно и минималистично, в стиле моих проектов и логотипов, но суть как на картинках: несколько проектов и ссылки на них».

**Визуальные анти-паттерны из ТЗ:** много скруглённых карточек, тяжёлые рамки, Bento grid, чёрно-красный киберпанк, неон, светящиеся кнопки, film grain поверх страницы, много фото, мелкий uppercase, подписи 10 px, сложные сетки на телефоне, сжатый desktop, горизонтальный скролл, функции только по hover, крошечные иконки-кнопки, hero на три экрана, заголовок на 90% ширины без причины. Клише: терминал для annFlow, глобус для VPN, винил для радио, крыло самолёта для путешествий. Кинематографичность должна идти от темпа, пустоты, масштаба, ритма, кадрирования и пауз, а не от плёнки, таймкодов, letterbox, glitch и VHS.

### Цвет
- Почти чёрный фон, мягкий белый текст, серый вторичный, **красный как подпись**: экономно, точечно.
- Если всё красное, акцент перестаёт быть акцентом.

### Изображения
Сайт должен выглядеть собранно **с отключёнными изображениями**. Изображения — улучшение, а не каркас. В v1 нет ни одной фотографии. Допустимо одно сильное изображение в hero или редкое изображение при раскрытии, но решение о портрете отложено.

## 6. Текущий дизайн v1 — подробно

### Структура страницы (сверху вниз)
1. **Header:** только текстовая ссылка «Portfolio ↗» справа, серым. Имени нет, потому что ниже стоит wordmark. Гамбургера нет: он не нужен на одной странице.
2. **Hero** (около 46% высоты экрана, чтобы снизу был виден первый проект): красный wordmark `@arsenynn` (SVG, 21rem шириной на телефоне, 30rem на desktop) → `projects / channels / things` серым → фраза засечками «an index of parallel things» → одна строка серым: «Один автор, семь параллельных линий: кино, заказное видео, разговор, эфир, системы, приватность и дорога».
3. **Индекс из семи проектов.** Без карточек: строки разделены тонкими линиями, как оглавление журнала.
4. **Work / Collaboration:** отделён более светлой линией, заголовок засечками, описание, кнопки Portfolio (primary) и Telegram.
5. **Footer:** «© @arsenynn 2026», год вычисляется при сборке.

### Анатомия строки проекта (телефон)
```
01  [знак NN / Ws / маска, если есть]
    Название засечками (или логотип вместо названия у annFlow)
    concept · chapters · identity        ← теги, точки красные
    Одна короткая фраза.
    ( Telegram ↗ )  ( Portfolio ↗ )  About +
    [раскрытый About: 1–2 коротких абзаца серым]
```
- Номер в левой колонке шириной 2rem (на desktop 8rem), табличные цифры, серый.
- Знак (`mark`) стоит над названием, высота 1.75rem; логотип (`logo`) заменяет название, высота 3.5rem.
- Длинное «Бессмысленность и скоротечность» переносится по словам, никогда не уменьшается. Перед `@` в `workflow@arsenynn` разрешён перенос.

### Кнопки
- Ссылки — кнопки-«пилюли» высотой 48 px с тонкой рамкой 1 px и стрелкой ↗, без заливки, свечения и теней.
- Primary-ссылка проекта: красная рамка и красный текст, при наведении заливается красным.
- Secondary: серая рамка, белый текст.
- About — текстовая кнопка «About +» / «About −» серым, чтобы не спорить со ссылками.
- Все основные ссылки видны **без** раскрытия About. Это правило владельца.

### About (accordion)
- Раскрытие внутри строки, без modal, popup и overlay. Раскрытый текст продолжает строку, а не становится карточкой.
- Анимация 200 ms: `grid-template-rows` 0fr → 1fr и opacity. При `prefers-reduced-motion` отключается.
- `aria-expanded`, `aria-controls`, нативная `<button>`, работает с клавиатуры (Enter, Space).
- Без JavaScript весь текст About просто виден.
- Раскрытие одного проекта не закрывает другие.

### Desktop
Та же структура, не другая. Контейнер до 72rem (1152 px), колонка номера 8rem, текст не шире 38rem, отступы между проектами больше. Текст на desktop не уменьшается.

### Design tokens (`src/styles/tokens.css`)
| Токен | Значение |
|---|---|
| `--color-bg` | `#0a0a0a` |
| `--color-text` | `#f2f2f0` |
| `--color-muted` | `#9a9a96` (контраст 7:1) |
| `--color-accent` | `#e5322d` (контраст 4.55:1, AA впритык) |
| `--color-line` / `--color-line-strong` | `#262624` / `#4a4a46` |
| `--font-ui` | системный: SF на Apple, Segoe / Roboto |
| `--font-display` | Playfair Display Variable (OFL-1.1, кириллица, self-hosted) |
| `--text-body` | 17 px телефон, 18 px desktop, line-height 1.5 |
| `--text-meta` | 15 px (теги, подписи) |
| `--text-title` | `clamp(26px … 44px)` |
| отступы | 8 / 16 / 24 / 40 / 64 px |
| `--tap` | 48 px |
| `--duration` | 200 ms |

Всего около 25 токенов. Направление можно менять в одном файле: акцент, фон, шрифт заголовков, плотность.

### Движение
Почти неподвижно. Есть только раскрытие About и переходы цвета у ссылок. Нет параллакса, кастомного скролла, курсоров, 3D, бесконечных анимаций.

### Доступность
Семантичный HTML, один `h1`, `h2` у проектов, видимый фокус (красная обводка), alt у логотипов, пустой alt у декоративных знаков, zoom не блокируется, все цели не меньше 44×44, смысл не передаётся только цветом.

## 7. Техника

### Стек
- **Astro 7** со статической сборкой, TypeScript для данных, обычный CSS с токенами. Без Tailwind, UI-библиотек и icon packs.
- **Один клиентский скрипт** (About), без React и `client:*`-островов.
- Шрифт заголовков self-hosted через `@fontsource-variable/playfair-display`, текст системным шрифтом.
- Логотипы: одноцветные векторизованы в SVG (potrace), многоцветный annFlow в WebP.

### Вес
Вся страница — один HTML около 27 KB с инлайновым CSS. Плюс шрифт около 40–50 KB на подмножество и логотипы: SVG 2–9 KB, WebP 30 KB. Сборка `dist/` занимает около 260 KB вместе с OG-картинкой.

### Модель контента
Весь контент и все URL лежат в `src/data/projects.ts` и `src/data/site.ts`, компоненты содержат только разметку.
```ts
type Project = {
  id; order; slug; title; tags: string[];
  shortDescription; longDescription?: string[];
  status: 'active' | 'coming-soon' | 'private'; statusLabel?;
  links: { label; url; type: 'telegram'|'website'|'portfolio'|'listen'|'other'; primary? }[];
  logo?: { src; width; height };   // вместо названия
  mark?: { src; width; height };   // знак над названием
  detailPageEnabled: boolean;      // будущие страницы проектов
}
```
Компоненты: SiteHeader, Hero, ProjectList, ProjectSection, ProjectActions, ProjectDetails, ActionLink, Collaboration, SiteFooter.

### Хостинг и сеть
- **GitHub Pages** из публичного репозитория, сборка через GitHub Actions при каждом push в `main`.
- **DNS в Cloudflare**, но **только DNS only**, без прокси. Это проверено на соседнем проекте Portfolio: прокси Cloudflare в России обрезает ответы примерно после 16 KB, и сайт ломается. Поэтому Cloudflare Pages, Workers и прокси не подходят.
- HTTPS через сертификат GitHub (Let's Encrypt).
- Домены `*.arsenynn.quest` (радио, VPN) принадлежат владельцу, продлеваются до 2026-11-15.
- Ограничение для v2: любые сторонние сервисы (видеохостинг, CDN, CMS, шрифты, embed) должны надёжно открываться из России. YouTube, Vimeo, Instagram и часть CDN там медленные или заблокированы.

### Как ведётся работа
- Документация по стандарту владельца в `docs/`: план, архитектура, ТЗ, журнал решений, реестр ссылок, ресерч дизайна, деплой.
- Над проектом работают AI-агенты (Claude Code в облачных сессиях): ветка → PR → merge. Поэтому архитектура должна оставаться простой, предсказуемой и документированной.
- Тестов нет. Проверка — сборка и браузер (Playwright) на ширинах телефона и desktop.

## 9. Что нужно выяснить в deep research

### Дизайн и UX
1. Какие сайты авторов, режиссёров, студий, музыкантов, независимых журналов и культурных институций 2024–2026 годов лучше всего решают задачу «один автор, много разных проектов»? Конкретные примеры с разбором: что взять, что нет.
2. Как сделать главную одновременно минималистичной и с характером, если логотипы проектов радикально разные (узкий гротеск, каллиграфия, рваная кисть, силуэт)? Лучшие практики «system + personality».
3. Как перейти от индекса ссылок (v1) к сайту с контентом (v2), не потеряв скорость и ясность главной? Паттерны навигации между индексом и страницами проектов.
4. Как показывать видео на телефоне кинематографично, но быстро: превью, постеры, автоплей без звука или нет, полноэкранный режим, вертикальное и горизонтальное видео?
5. Как подавать фото и длинные тексты (главы, литература, эссе) редакционно: типографика длинного чтения на телефоне, сочетание текста и изображений.
6. Плеер радио, который продолжает играть при переходах между страницами: UX и технологии (View Transitions, persistent islands, SPA-режим).
7. Типографика: какие open-source шрифты с хорошей кириллицей лучше подходят под «quiet editorial cinematic», чем Playfair Display? Пары засечки + гротеск, variable fonts, оптические размеры.
8. Тёмная тема: оптимальные значения фона, текста и акцента, контраст красного на чёрном (APCA и WCAG), нужна ли светлая тема.
9. Motion: какие минимальные приёмы (View Transitions API, scroll-driven animations) добавляют кинематографичность без вреда скорости и доступности.
10. Микротексты: как писать короткие описания проектов, чтобы они были особенными, а не банальными.

### Техника для v2
11. Astro 7: content collections, Content Layer, server islands, View Transitions, image и video pipeline. Что из этого нужно именно нам?
12. Где хранить и раздавать видео, чтобы оно стабильно работало в России и за рубежом: self-hosted HLS, Cloudflare Stream (с учётом проблемы прокси), Bunny Stream, Mux, Kinescope, VK Видео, Rutube embed? Сравнение по скорости из РФ, цене, качеству плеера и приватности.
13. Изображения: AVIF/WebP, responsive srcset, где хостить (в репозитории или на внешнем CDN, доступном из РФ).
14. Контент из Telegram: стоит ли автоимпорт постов (Bot API, MTProto, экспорт) или лучше ручное курирование в Markdown или CMS? Какая headless CMS (Keystatic, Decap, TinaCMS, Sanity, Payload) удобна одному автору и AI-агентам и работает со статическим сайтом на GitHub Pages?
15. Нужно ли уходить с GitHub Pages на другой хостинг, когда появятся видео и динамика? Какие варианты надёжно открываются из России без прокси Cloudflare?
16. Аналитика без трекеров и cookie-баннера, если владелец решит её добавить (Plausible, Umami self-hosted), с учётом РФ.
17. SEO и превью в Telegram для страниц проектов и отдельных материалов: OG-картинки на каждую страницу, генерация при сборке.
18. Производительность: бюджеты на телефоне в мобильной сети (LCP, INP, CLS), как удержать их с видео и фото.
19. Двуязычность RU/EN в будущем: как заложить сейчас без лишней сложности.

### Формат ответа, который нужен
- Конкретные рекомендации с обоснованием и источниками, а не общие советы.
- Примеры реальных сайтов со ссылками.
- Для технологий: сравнение вариантов, цена, доступность из России, сложность поддержки одним человеком и AI-агентами.
- Отдельно: что сделать в v1 сейчас (полировка), что в v2, что отложить.
- Учитывать все ограничения из этого документа: приоритеты, анти-паттерны, Россия, без прокси Cloudflare, без трекеров, минимум JavaScript, mobile-first.
