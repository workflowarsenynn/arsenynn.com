[Этот проект](https://t.me/bessmislennost) устроен не как текстовый AI-бот в вакууме. Он живёт внутри Telegram-среды, а значит работает не только с репликами, но и с медиа: voice, audio, photo, video\_note, sticker.

Один из базовых узлов выглядит так:

```
c.execute("""
CREATE TABLE IF NOT EXISTS ann_message_media(
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  chat_id INTEGER NOT NULL,
  msg_id INTEGER NOT NULL,
  user_id INTEGER,
  media_type TEXT NOT NULL,
  file_id TEXT,
  file_unique_id TEXT,
  mime_type TEXT,
  caption TEXT,
  created_at TEXT NOT NULL,
  UNIQUE(chat_id, msg_id, media_type)
)
""")
```

• **ann\_message\_media**  
Отдельная таблица для медиа.  
То есть проект хранит не только текст сообщений, но и сами типы медиа-событий.

• **chat\_id, msg\_id, user\_id**  
Фиксируют, где именно появилось медиа, в каком сообщении и от какого пользователя.

• **media\_type**  
Показывает, что это было: голосовое, фото, стикер, кружок, аудио.

• **file\_id, file\_unique\_id**  
Позволяют потом снова обратиться к этому объекту через Telegram.

• **caption**  
Если у медиа была подпись, она тоже сохраняется.

• **UNIQUE(chat\_id, msg\_id, media\_type)**  
Защита от дублей.  
Один и тот же медиа-объект не должен записываться в память дважды.

Теперь сам момент сохранения:

```
def ann_save_media(chat_id: int, msg_id: int, user_id: int | None, media_type: str,
                   file_id: str | None, file_unique_id: str | None,
                   mime_type: str | None = None, caption: str | None = None):
    c.execute("""
      INSERT OR IGNORE INTO ann_message_media
      (chat_id, msg_id, user_id, media_type, file_id, file_unique_id, mime_type, caption, created_at)
      VALUES(?,?,?,?,?,?,?,?,?)
    """, (...))
```

• **ann\_save\_media(...)**  
Функция сохраняет медиа в память проекта.

• **INSERT OR IGNORE**  
Если такая запись уже есть, база не создаёт дубль.  
Это важно для стабильной работы в Telegram, где одно и то же событие иногда может прийти повторно.

• **media\_type, file\_id, caption**  
Проект запоминает не просто “было какое-то медиа”, а его тип, идентификатор и контекст.

То есть бот хранит не только разговор в словах, но и разговор в формах.

А дальше у проекта есть ещё один слой, уже публикационный:

```
c.execute("""
CREATE TABLE IF NOT EXISTS ann_story_state(
  id INTEGER PRIMARY KEY CHECK (id=1),
  last_story_at TEXT,
  last_source_chat_id INTEGER,
  last_source_msg_id INTEGER,
  last_file_unique_id TEXT,
  cooldown_until TEXT,
  note TEXT
)
""")
```

• **ann\_story\_state**  
Это таблица состояния Stories.

• **last\_story\_at**  
Когда Story публиковалась в последний раз.

• **last\_source\_chat\_id, last\_source\_msg\_id**  
Откуда был взят исходный материал.

• **last\_file\_unique\_id**  
Какой именно файл уже использовался.

• **cooldown\_until**  
Когда снова можно публиковать.

То есть проект работает с медиа не как с мёртвыми вложениями.  
Он помнит их, различает, связывает с источником и управляет их повторным появлением.

Именно поэтому этот проект живет не только в тексте.  
Он живет в материале: в голосе, изображении, стикере, кружке, подписи, публикации, повторном возвращении файла в поток.

И в этом смысле он устроен не как “чат с AI”, а как система, встроенная в реальную медиа-жизнь Telegram.
