---
title: "Why I wrote this code not for the sake of automation"
---

Projects like this are usually described in terms of convenience: the bot answers, saves something, publishes something, searches for something. But in my case the task was different from the start.

I didn't write this code to speed up routine.
I wrote it so that material wouldn't vanish, a conversation wouldn't reset after every line, and philosophy would exist not only in text but also in the behaviour of the system.

You can see the same in the logic of a reply:

```
messages = [
    {"role": "system", "content": system_prompt},
    {"role": "system", "content": profile_block},
    {"role": "user", "content": ctx},
]
```

A reply is built not from one last line.
The system assembles the situation of the conversation: the frame, the person's profile, the accumulated context.
So it doesn't just react, it holds duration.

But the most important point is that the project lives not only in replies.

```
queue_profile_update(int(user_id))
picked = pick_relevant_content(query_text, top_k=CONTENT_TOP_K)
ANN_PHILOSOPHY_STYLE = style
```

What matters here:

**• queue\_profile\_update(...)**
The system keeps working between messages too. It updates its idea of a person not instantly but as material accumulates.

**• pick\_relevant\_content(...)**
The material doesn't lie in a dead archive. It returns to a conversation by meaning.

**• ANN\_PHILOSOPHY\_STYLE = style**
Philosophy here isn't attached alongside. It's built into behaviour and affects the very principle of speech.

So this isn't just a bot but an environment.
Here a conversation doesn't reset, material doesn't vanish, and philosophy works as part of the system's behaviour.
"[Bessmyslennost i skorotechnost](https://t.me/bessmislennost)" is the environment where this logic lives in action.
